# Edit جديد على المشروع الحالي: تحسين صفحة طلب الأوردر العامة + إصلاح Sidebar Scroll + إعادة تنظيم بعض صفحات ERP

أنت الآن داخل مشروع ERP فعلي موجود بالفعل.

المطلوب ليس إنشاء مشروع جديد، وليس إعادة بناء النظام من الصفر.  
المطلوب هو تنفيذ هذا الـ Edit فقط على المشروع الحالي بناءً على التعديلات التالية.

---

## 1. تعديل صفحة طلب الأوردر العامة لكل Tenant / Store

### المطلوب

صفحة طلب الأوردر يجب أن تكون صفحة عامة خاصة بالعميل النهائي End User وليست صفحة داخل نظام ERP.

كل Tenant / Company / Store مشترك معنا يجب أن يكون له رابط طلب خاص به باستخدام slug فريد.

مثال:

```txt
/order/{tenantSlug}

أمثلة:

/order/market-plus
/order/abu-omar-market
/order/kenoz-supermarket
المطلوب في بيانات المتجر / الشركة

تأكد أن كل Tenant أو Store لديه:

tenantSlug: string;
publicOrderingEnabled: boolean;
publicStoreName: string;
publicStoreLogo?: string;
publicWhatsappNumber: string;
publicPhone?: string;
publicAddress?: string;
publicArea?: string;
publicDescription?: string;
deliveryEnabled: boolean;
pickupEnabled: boolean;
deliveryFee: number;
minimumOrderAmount?: number;
showProductStock: boolean;
allowOutOfStockDisplay: boolean;
شروط الـ Slug
يكون slug خاص بكل شركة / متجر.
slug يكون فريد ولا يتكرر.
slug يكون lowercase.
لا يحتوي على مسافات.
يسمح فقط بـ letters, numbers, hyphen.
لو slug غير موجود أو صفحة الطلب غير مفعلة، اعرض صفحة 404 عامة بدون كشف أي بيانات داخلية.

15. حل مشكلة Scroll الخاصة بالـ Sidebar
المشكلة

عند الضغط على أي قسم في الـ Sidebar، الـ Scroll الخاص بالـ Sidebar نفسه يعمل reset ويرجع لأول القائمة.

المطلوب أن يظل Scroll الخاص بالـ Sidebar في نفس مكانه.

مثال:

لو المستخدم كان في آخر الـ Sidebar وضغط على قسم، يجب أن يظل الـ Sidebar في آخر القائمة ولا يرجع للأعلى.

المطلوب تقنيًا
لا تجعل Sidebar component يعاد mount عند تغيير الصفحة.
اجعل Sidebar داخل Persistent Layout.
لا تغيّر key الخاص بالـ Sidebar عند تغيير route.
لا تستخدم conditional rendering يسبب unmount/remount للـ Sidebar.
احفظ scrollTop الخاص بالـ Sidebar في ref أو sessionStorage.
عند تغيير Route:
احفظ قيمة sidebar.scrollTop قبل التنقل.
بعد التنقل أعد تطبيق نفس scrollTop.
لا تستخدم scrollTo top على Sidebar.
لو يوجد useEffect يعمل reset للـ Sidebar scroll، أزله أو عدله.
اجعل active menu item واضحًا بدون تحريك القائمة للأعلى.
لا تستخدم autoFocus أو scrollIntoView يسبب تحريك الـ Sidebar إلا عند الحاجة وبشكل اختياري.
Acceptance Criteria
الضغط على أي عنصر في Sidebar لا يرجع Sidebar لأول القائمة.
Sidebar يظل في نفس موضع Scroll.
الصفحة نفسها يمكن أن تبدأ من أعلى، لكن Sidebar لا يرجع للأعلى.
Navbar وSidebar لا يحدث لهم Flicker.
لا يحدث Full Refresh عند التنقل الداخلي.

22. Security Logs

سجّل في Security Logs:

Rate limit exceeded.
Invalid tenantSlug.
Invalid product IDs.
Quantity manipulation attempt.
Suspicious payload.
Repeated spam attempts.

23. Acceptance Criteria

بعد التنفيذ يجب أن يتحقق الآتي:

لكل Tenant / Store رابط طلب عام باستخدام slug.
صفحة الطلب العامة لا تظهر داخل ERP.
صفحة الطلب العامة تستخدم UX شبيه بتطبيقات الطلب وليس كاشير.
المنتجات تظهر بتفاصيل واضحة وليس مجرد مربعات.
Product details يظهر داخل Modal / Bottom Sheet.
السلة تعرض Breakdown كامل للأسعار.
Checkout يعمل بخطوات واضحة.
الطلب يتم حفظه في قاعدة البيانات.
رسالة واتساب تُبنى من الطلب المحفوظ.
إعدادات طلب الأوردر تتحكم في الصفحة العامة.
صفحة طلب الأوردر القديمة غير موجودة في Sidebar.
صفحة إعدادات طلب الأوردر موجودة داخل ERP.
طلبات العملاء تظهر داخل ERP للإدارة.
يمكن تحويل طلب العميل إلى فاتورة بيع.
عند التحويل إلى فاتورة يتم خصم المخزون.
Sidebar لا يرجع للأعلى عند الضغط على قسم.
تم إضافة صفحة الرئيسية قبل لوحة التحكم.
Dashboard الحالية ما زالت موجودة.
حركة المخزون أصبحت داخل صفحة المخزون.
الأدوار والصلاحيات أصبحت داخل صفحة الموظفين.
Sidebar النهائي لا يحتوي على صفحات مكررة.
كل شيء يعمل حسب الصلاحيات.
كل تعديل مهم يسجل Activity Log.
المحاولات المشبوهة تسجل Security Logs.
لا توجد أسرار أو بيانات اتصال قاعدة البيانات داخل الكود.
الكود منظم وقابل للتطوير.
24. تعليمات تنفيذ نهائية

ابدأ بالخطوات التالية بالترتيب:

افحص الوضع الحالي لصفحة طلب الأوردر.
أزل صفحة طلب الأوردر من Sidebar الداخلي.
أنشئ أو عدّل صفحة Public Tenant Order Page باستخدام tenantSlug.
صمم صفحة الطلب بفلو UX مناسب للعميل النهائي وليس كاشير.
أنشئ Product Details Modal / Bottom Sheet.
أنشئ Cart UX واضح.
أنشئ Checkout Flow متعدد الخطوات.
أنشئ أو حدّث APIs الخاصة بصفحة الطلب العامة.
أضف validation وsanitization وrate limit.
احفظ الطلبات في قاعدة البيانات.
أنشئ WhatsApp message من البيانات المحفوظة.
أضف صفحة إدارة طلبات العملاء داخل ERP.
أضف صفحة إعدادات طلب الأوردر داخل ERP.
أصلح Sidebar scroll persistence.
أضف صفحة الرئيسية قبل Dashboard.
انقل حركة المخزون داخل صفحة المخزون.
انقل الأدوار والصلاحيات داخل صفحة الموظفين.
حدّث Sidebar النهائي.
حدّث الصلاحيات.
أضف Activity Logs وSecurity Logs.
اختبر كامل الـ Flow.
اكتب تقرير بالملفات التي تم تعديلها والجداول التي تم إنشاؤها.

لا تنشئ مشروعًا جديدًا.
لا تستخدم Mock Data كبديل نهائي.
لا تترك صفحة الطلب داخل السيستم الداخلي.
لا تكشف بيانات إدارية في الصفحة العامة.
لا تعتمد على حماية الواجهة فقط.
نفّذ الحماية في السيرفر والـ API والـ Database Layer.
