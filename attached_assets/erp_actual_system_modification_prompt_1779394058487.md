# برومبت تعديل فعلي على نظام ERP الحالي للسوبرماركت والبقالات

استخدم هذا البرومبت داخل الـ AI Coding Agent وهو فاتح مشروع الـ ERP الحالي بالفعل.  
المطلوب ليس إنشاء تصميم جديد من الصفر، وليس إضافة أفكار على برومبت قديم.  
المطلوب هو تعديل الكود الفعلي الموجود حاليًا داخل المشروع، وربط الصفحات بالبيانات الحقيقية الموجودة في النظام قدر الإمكان.

\---

## المطلوب العام

عدّل نظام ERP الحالي الخاص بالسوبرماركتس والبقالات بحيث يتم تنفيذ التعديلات التالية على السيستم الفعلي:

1. تفعيل سجل نشاط النظام الحقيقي وربطه ببيانات المتاجر والموظفين.
2. إضافة Modal لإضافة موظف جديد داخل صفحة الموظفين.
3. إضافة Modals عمليات المخزون داخل صفحة المخزون.
4. دمج التصنيفات داخل صفحة المنتجات وإلغاء صفحة التصنيفات من الـ Sidebar.
5. حل مشكلة رجوع Scroll لأعلى عند التنقل بين أقسام الـ Sidebar.
6. تطوير المرتجعات لتكون من المبيعات الفعلية مع إمكانية طباعة فاتورة مرتجع.
7. إضافة قسم الدعم الفني وربطه بلوحة السوبر أدمن.
8. إعادة تصميم Splash / Hero الموجود في صفحة Login.
9. إضافة صفحة طلب أوردرات مربوطة بمنتجات المتجر الفعلية وإرسال تفاصيل الطلب على واتساب.
10. إصلاح صفحات السوبر أدمن التي لا تعمل:

    * المشرفون
    * سجل النشاطات
    * صحة النظام
11. تطوير فورم إضافة الشركات من صفحة اللوجن ومن لوحة السوبر أدمن ليضم كل التفاصيل المطلوبة.

\---

# تعليمات تنفيذ مهمة جدًا

* لا تنشئ مشروعًا جديدًا.
* لا تستبدل النظام الحالي بالكامل.
* عدّل الملفات الحالية قدر الإمكان.
* حافظ على نفس الـ Design System الحالي لو موجود.
* حافظ على نفس طريقة إدارة الحالة الحالية سواء Zustand أو Redux أو Context أو React Query أو غيره.
* حافظ على نفس نظام الـ Routing الحالي.
* لا تستخدم بيانات وهمية بدل البيانات الحقيقية إلا لو المشروع لا يحتوي Backend حاليًا.
* لو المشروع يستخدم Mock Data، اربط التعديلات بنفس Mock Store الحالي بطريقة قابلة للتحويل لاحقًا إلى API.
* كل عملية مهمة يجب أن تُسجل في Activity Logs.
* كل صفحة يجب أن تكون RTL ومتوافقة مع اللغة العربية.
* لا تجعل الأنيميشن يؤثر على سرعة التشغيل.
* لا تكسر أي صفحة موجودة حاليًا.

# 1\. تفعيل سجل نشاط النظام الحقيقي System Activity Logs

## المشكلة الحالية

قسم سجل النشاط لا يعرض بيانات حقيقية مرتبطة بكل متجر وكل موظف، أو لا يعمل بالشكل المطلوب.

# 2\. إضافة Modal لإضافة موظفين في صفحة الموظفين

## المطلوب

داخل صفحة الموظفين الحالية أضف زر:

```text
إضافة موظف جديد
```

عند الضغط عليه يفتح Modal وليس صفحة منفصلة.

## حقول Modal إضافة الموظف

* الاسم الكامل
* رقم الهاتف
* البريد الإلكتروني
* كلمة المرور
* تأكيد كلمة المرور
* الدور Role
* الفرع Branch
* الشركة / المتجر حسب بنية النظام
* الحالة:

  * Active
  * Inactive
* الصورة الشخصية اختياري
* حد الخصم المسموح به
* الراتب اختياري
* تاريخ التعيين
* العنوان
* الرقم القومي / رقم الهوية اختياري
* ملاحظات داخلية
* Custom Permissions اختيارية

## Validation

* الاسم مطلوب.
* الهاتف مطلوب.
* البريد مطلوب ويجب أن يكون صحيحًا.
* لا تسمح بتكرار البريد.
* لا تسمح بتكرار رقم الهاتف.
* كلمة المرور لا تقل عن 8 أحرف.
* تأكيد كلمة المرور يجب أن يطابق كلمة المرور.
* الدور مطلوب.
* الفرع مطلوب لو الدور مرتبط بفرع.

## بعد الحفظ

* أضف الموظف فعليًا لقائمة الموظفين.
* اربطه بالمتجر والفرع.
* اعرض Toast Success.
* أغلق الـ Modal.
* حدّث الجدول بدون Refresh كامل.
* سجّل العملية في Activity Logs.

## Modal تعديل موظف

لو صفحة الموظفين بها تعديل حاليًا، حافظ عليه، لكن اجعل نفس الـ Modal قابلًا للاستخدام للإضافة والتعديل.

# 5\. حل مشكلة Scroll Reset عند التنقل من الـ Sidebar

## المشكلة

عند الضغط على قسم جديد في الـ Sidebar، الـ Scroll يرجع من أول الصفحة أو يحصل تحميل كامل مزعج.

## المطلوب

حل المشكلة على مستوى الـ Routing والـ Layout.

## المطلوب تقنيًا

* اجعل Sidebar و Navbar داخل Persistent Layout ولا يعاد تحميلهم مع كل صفحة.
* لا تستخدم `window.location.href` في التنقل الداخلي.
* استخدم Link / NavLink / router.push حسب الفريمورك.
* نفّذ Scroll Restoration لكل Route.
* احفظ موضع Scroll لكل صفحة داخل sessionStorage أو state.
* عند الرجوع لصفحة تمت زيارتها، ارجع لنفس موضع Scroll.
* عند فتح صفحة لأول مرة فقط، ابدأ من أعلى.
* لا تعرض Splash Screen أو Full Page Loader عند كل تنقل.
* استخدم Skeleton داخل محتوى الصفحة فقط لو البيانات يتم تحميلها.
* حافظ على Smooth Page Transition بدون Flicker.

## Acceptance Criteria

* التنقل بين أقسام Sidebar لا يعيد تحميل التطبيق كاملًا.
* Sidebar لا يتحرك ولا يختفي.
* Navbar لا يعاد Render بشكل ملحوظ.
* لو المستخدم كان في منتصف صفحة المبيعات وذهب لصفحة أخرى ثم عاد، يرجع لنفس موضعه السابق.
* لا يحدث Jump مزعج لأعلى إلا عند أول زيارة لصفحة جديدة.

# 6\. تطوير قسم المرتجعات Returns

## المطلوب

قسم المرتجعات يجب أن يكون من المبيعات الفعلية وليس إدخال يدوي عشوائي.

أضف زر:

```text
إضافة مرتجع
```

## Flow إضافة مرتجع

عند الضغط على الزر افتح Modal أو Drawer.

### Step 1: البحث عن فاتورة بيع فعلية

البحث بواسطة:

* رقم الفاتورة
* اسم العميل
* رقم الهاتف
* التاريخ
* اسم الكاشير

### Step 2: اختيار الفاتورة

بعد اختيار الفاتورة اعرض:

* رقم الفاتورة
* تاريخ البيع
* الكاشير
* العميل
* طريقة الدفع
* المنتجات
* الكمية المباعة
* الكمية التي تم إرجاعها سابقًا
* الكمية المتاحة للارتجاع
* السعر
* الإجمالي

### Step 3: تحديد المرتجع

* اختيار منتج أو أكثر.
* تحديد الكمية المرتجعة لكل منتج.
* دعم مرتجع كامل.
* دعم مرتجع جزئي.

### Step 4: سبب المرتجع

الأسباب:

* منتج تالف
* خطأ في الفاتورة
* العميل غير رأيه
* منتج منتهي الصلاحية
* أخرى

### Step 5: طريقة رد المبلغ

* Cash
* Card Refund
* Wallet
* Store Credit

## Validation

* لا تسمح بإرجاع كمية أكبر من المتاحة.
* لا تسمح بإرجاع نفس الكمية مرتين.
* لا تسمح بمرتجع بدون فاتورة أصلية.
* لا تسمح بمرتجع بدون سبب.
* نفّذ الصلاحيات الخاصة بالمرتجعات.

## بعد إنشاء المرتجع

* أنشئ Return Record.
* اربطه بالفاتورة الأصلية.
* حدّث المخزون تلقائيًا إذا كان المنتج صالحًا للرجوع للمخزون.
* حدّث تقارير المبيعات والأرباح.
* سجّل العملية في Activity Logs.
* اعرض Toast Success.

## طباعة فاتورة مرتجع

أضف زر:

```text
طباعة فاتورة مرتجع
```

الفاتورة تحتوي على:

* شعار المتجر
* اسم المتجر
* رقم المرتجع
* رقم الفاتورة الأصلية
* التاريخ
* اسم الكاشير
* اسم العميل إن وجد
* المنتجات المرتجعة
* الكمية
* السعر
* سبب المرتجع
* المبلغ المسترد
* طريقة رد المبلغ
* QR Code اختياري
* Footer من إعدادات الفاتورة

# 13\. اختبارات القبول النهائية

بعد تنفيذ التعديلات، تأكد من الآتي:

## Activity Logs

* أي إضافة موظف تظهر في سجل النشاط.
* أي تعديل مخزون يظهر في سجل النشاط.
* أي مرتجع يظهر في سجل النشاط.
* أي طلب أوردر يظهر في سجل النشاط.
* السوبر أدمن يرى كل السجلات.
* مدير الفرع يرى سجلات فرعه فقط.

## Employees

* زر إضافة موظف يفتح Modal.
* الحفظ يضيف الموظف فعليًا.
* Validation يعمل.
* الجدول يتحدث بدون Refresh.

## Inventory

* كل Modal يفتح ويعمل.
* تعديل الكمية يحدث المخزون.
* التحويل بين الفروع لا يسمح بكمية أكبر من المتاح.
* الهالك يخصم من المخزون.

## Products \& Categories

* التصنيفات موجودة داخل المنتجات.
* التصنيفات غير موجودة في Sidebar.
* إضافة وتعديل التصنيف يعملان.
* لا يمكن حذف تصنيف به منتجات بدون معالجة.

## Scroll

* التنقل من Sidebar لا يعمل Full Reload.
* Sidebar و Navbar ثابتين.
* الرجوع لصفحة سابقة يحافظ على Scroll Position.

## Returns

* المرتجع يتم من فاتورة بيع فعلية.
* لا يمكن إرجاع كمية أكبر من المتاح.
* يمكن طباعة فاتورة مرتجع.
* المخزون يتحدث بعد المرتجع.

## Support Center

* المتجر يرسل تذكرة دعم.
* التذكرة تظهر في Super Admin.
* السوبر أدمن يستطيع الرد وتغيير الحالة.

## Login Splash

* التصميم الجديد يظهر.
* لا يبطئ صفحة Login.
* Responsive على الموبايل.

## Order Request

* المنتجات تأتي من منتجات المتجر.
* لا يمكن اختيار كمية أكبر من المتاح.
* رسالة واتساب تحتوي على كل التفاصيل.
* الطلب يتم حفظه في النظام.
* يمكن تحويل الطلب إلى فاتورة بيع.

## Super Admin

* صفحة المشرفون تعمل.
* صفحة سجل النشاطات تعمل.
* صفحة صحة النظام تعمل.

## Company Form

* فورم إضافة الشركة من Login مكتمل.
* فورم إضافة الشركة من Super Admin مكتمل.
* إنشاء الشركة ينشئ المالك والفرع والإعدادات الافتراضية.

# 14\. تعليمات نهائية للـ AI Coding Agent

ابدأ بفحص بنية المشروع الحالية:

1. افحص Routes.
2. افحص Layout.
3. افحص Sidebar.
4. افحص Auth / Roles / Permissions.
5. افحص Data Stores أو API Services.
6. افحص صفحات:

   * Employees
   * Inventory
   * Products
   * Returns
   * Login
   * Super Admin
7. نفّذ التعديلات على مراحل بدون كسر النظام.
8. بعد كل مرحلة تأكد أن المشروع يعمل.
9. لا تحذف وظائف موجودة إلا لو كانت مكررة أو معطلة.
10. استخدم Components reusable بدل تكرار الكود.
11. اجعل الكود قابلًا للتحويل لباك إند حقيقي.
12. أضف TypeScript types واضحة لكل كيان جديد.
13. أضف Activity Log لكل Action مهم.
14. أصلح أي import أو route أو permission guard يمنع صفحات السوبر أدمن من العمل.
